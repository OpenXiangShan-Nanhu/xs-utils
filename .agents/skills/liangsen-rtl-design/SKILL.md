# Liangsen RTL Design

面向通用可综合 RTL，而非某个模块或某种微架构。适用于独立 `.sv`、生成器模板及内嵌 SV；不把特定 FIFO、仲裁器或协议的行为推广成通用要求。纯审查给出发现，修改任务才编辑代码，始终限制在用户指定范围内。

## 必须遵守的规则

### 1. 组合逻辑优先使用 wire、generate for 和 assign

- 组合计算尽量使用 `wire` + `assign`；批量地址、掩码、前缀、数组归约、译码和数据选择优先使用 `for (genvar i = ...; ...; i++)` 展开连续赋值。简单连接、原生归约和单条表达式直接连续赋值，无需添加循环或进程包装。
- 只有 `case`、多级分支等过程式结构能改善可读性时，才使用 `logic` + `always_comb`，并用阻塞赋值 `=`；需要遍历时可在其中使用过程式 `for`。各执行路径必须完整赋值，避免默认赋值后覆盖。
- 批量寄存器更新默认使用 `always_ff` + 过程式 `for`，用非阻塞赋值 `<=`；按时钟、复位与控制语义合理组织进程，不无故逐元素生成独立进程。
- generate 循环可将相关 `assign`、局部参数和模块例化放在一起；依赖循环索引的静态切片、位宽和实例参数使用 `genvar`。不要为了移出 generate 而引入逐 bit 循环、全宽掩码或冗余中间数组。
- generate 的条件和循环边界必须在展开时确定。运行时条件可用于 `assign` 表达式，运行时索引可用于合法的数组访问或固定宽度动态切片；过程式分支明显更清晰时按上述规则使用 `always_comb`。
- 改写时保留位宽、符号、优先级及未知值语义，尤其核对过程式 `if` 与三目表达式的未知值处理差异。

### 2. 编译期配置使用外层 generate if，可省略区域关键字

- generate 语句不必包裹 `generate ... endgenerate`；默认在模块体或 generate 块中直接写 `if (CONST_EXPR) begin : name ... end` 或 `for (genvar i = ...; ...; i++) begin : name ... end`。显式区域关键字仍可使用，分支及循环体保留 `begin/end` 和具名作用域。
- 特性开关、实现模式等编译期参数用外层 generate `if/else` 选择实现；分支内优先使用 `wire`、generate 循环和 `assign`，可读性需要时采用 `always_comb`。
- 不将全局模式开关重复嵌入每 lane 的循环体、过程式 if 或三目表达式；依赖 `genvar` 的逐 lane 边界选择可在 generate 循环内使用 `if`。参数参与位宽、索引和普通算术本身不受此限制。
- 公共逻辑提取到分支外，不在各分支复制；运行时输入控制使用连续赋值表达式或过程式 `if/case`，不能放进 generate 条件。

### 3. 信号默认在循环外集中声明

- 数据临时量、向量、数组和矩阵默认在模块作用域集中声明；共享数据保持在循环及 generate 分支之外，通过元素或切片索引访问。
- 当位宽或类型依赖 `genvar`，或局部作用域能明显改善独立实例及连线的可读性时，允许在具名 generate 块内声明必要的 `localparam`、`wire`、`logic`；不为遵守集中声明而扩大位宽或制造冗余转接。
- 过程式循环体内仍不声明局部数据变量；`integer/genvar` 循环控制索引可在 for 头部声明，但不能兼作归约累加器。
- 每行只声明一个变量；即使类型和位宽相同，也不要用逗号把多个变量合并在同一条声明中。
- 过程式目标使用 `logic`；连续驱动或子模块输出使用 `wire`。不要把 wire 连续赋值改成仅初始化一次的 logic 声明。

### 4. 每 bit 单次赋值

**一次组合求值或一次时序更新内，每个实际目标 bit 最多赋值一次；同一互斥条件结构中的多分支赋值算一次。** 按驱动源、索引映射和可执行路径检查，不按赋值语句数量机械统计。

- 组合目标每 bit 必须在所有路径恰好赋值一次；时序目标允许在未使能时不赋值以保持状态。
- 完整的 `if/else`、`case/default` 可在各互斥分支赋值同一目标；分散的多个 if 不得仅凭“通常不会同时触发”视为互斥。
- 禁止“先默认赋值，再覆盖”、整向量/整数组清零后重写部分元素、临时结果算出后原地修正。使用完整互斥分支、单一表达式或独立中间阶段。
- SV 赋值右值、条件判断和端口实参中的表达式尽量一行写完，最多两行。复杂表达式按校验、选择、使能等语义拆成具名中间信号，便于定位未覆盖条件；不把长逻辑硬挤到一行。拆分时保留位宽、符号、优先级及未知值语义。参见 [表达式拆分](references/rtl-patterns.md#表达式拆分)。
- 循环可写不同元素或不重叠切片；审查动态索引、地址冲突和位宽截断，证明不同迭代不会写同一 bit。无法证明时改为按目标组织选择逻辑。
- 每 bit 仅一个有效驱动源；互斥 generate 分支中只有被选择的实现存在，不算多驱动。
- 循环索引递增和跨时钟周期更新不违反规则。`counter <= counter + delta` 的状态递推不等于同一组合求值中的反复累计。

### 5. 手写归约必须使用数组阶段

- 禁止 `acc = acc op term[i]`、`acc += ...`、`result |= ...` 等单变量循环归约；标量或向量均禁止，藏进函数/任务同样禁止。
- 求和、计数、AND/OR/XOR、min/max、前缀与优先级累计都使用阶段数组或树节点数组，作用域遵循第 3 条；seed 与后续目标分离，每个元素写一次。
- 数组不是形式包装：反复写 `stage[0]`、先初始化整个数组再覆盖、通过后续迭代覆盖结果实现优先级仍违规。
- 顺序扫描与树形归约均可，但须按依赖顺序写不同阶段/节点。数组写法不自动等于平衡树；不要在纯风格重构中擅自改变关键路径结构。
- `|mask`、`&mask`、`^mask` 等原生归约表达式没有可变累加器，可以直接使用；不要求为它们制造无意义数组。
- 写法与反例见 [references/rtl-patterns.md](references/rtl-patterns.md)；实施或审查归约、前缀、索引写入时读取该文件。

### 6. 分支格式、功能块组织与 function

- 少用 SV `function`；重复出现的硬件逻辑用职责单一的小模块复用，而不是封装成函数。保留的函数在函数作用域开头声明临时量，仍遵守单次赋值；不得借函数或任务隐藏重复累计或共享可变状态。
- `if`、`else if`、`else` 和 `case` 的每个分支都必须用 `begin/end` 包住，包含无 `else` 的 `if`、`case` 的 `default` 和 generate 条件分支。即使只有一条语句，分支体也必须另起一行并缩进；`begin` 放在条件或分支标签所在行，`end` 另起一行，可接 `else if` 或 `else`。
- 连续语句属于同一个小功能点或同一连贯计算过程时，可以紧接着写，不必额外插入空行；不同小功能点之间用空行分隔，使每个视觉代码块只包含一个小功能点。
- 必要的注释放在对应的小功能块前，说明用途、不明显的约束或时序原因，不逐句复述代码。修改逻辑时同步维护相关注释。

### 7. 端口声明与模块例化格式

- SV 模块的输入、输出必须显式声明 `wire` 或 `logic`；输入统一使用 `input wire`，`inout` 使用 `wire`。
- 只有端口本身直接在 `always_comb`、`always_ff` 或其他 `always` 块中赋值的输出使用 `output logic`；由 `assign`、子模块输出或其他连续连接驱动的输出统一使用 `output wire`。内部寄存器经 `assign` 连到输出时，输出仍是 `wire`。
- 同一端口列表每行声明一个端口，用空格纵向对齐方向、`wire/logic`、packed 位宽和端口名；标量在位宽列留空，使标量和向量端口名对齐。修改位宽或名称后重新检查整组对齐，内嵌 SV 同样遵守。
- SV 模块例化时，每个参数覆盖（如 `.WIDTH(WIDTH)`）和每个端口连接各占一行；即使只有一个参数或端口，也单独写在列表括号内的一行。
- Scala/Chisel 的 SvImpl 优先使用 Chisel 类型声明端口；`io_` 开头的信号统一收进 `val io = IO(new Bundle { ... })`，字段去掉 `io_` 前缀，调用处使用 `core.io.xxx`。已有具名 Bundle 可继续复用，时钟和复位保持独立 `IO`。
- `valid(1b)-bits-ready(1b)` 信号组使用 `Decoupled(payload)`，输入端使用 `Flipped(Decoupled(payload))`；`valid(1b)-bits` 信号组使用 `Valid(payload)`，按方向使用 `Input/Output` 或 `Flipped`，不得拆成独立握手字段。
- 多路 packed valid/ready 掩码保留为 `UInt(laneCount.W)` 和相应 packed bits，不能当作单个握手组；也不因参数暂时为 1 而改变字段类型。
- Bundle 层级展平后的端口名、方向和位宽须与 SV 模板一致；重构时同步封装、直接调用处及测试，检查生成接口与模板匹配。

### 8. 需要复位的寄存器一律使用异步复位

- 禁止同步复位。SV 的时序块必须在敏感列表中写出复位的有效边沿，例如高有效 `always_ff @(posedge clock or posedge reset)`，并在块内优先处理复位。
- Chisel 使用 `RequireAsyncReset`、显式设置 `Module.ResetType.Asynchronous`，或用 `withReset` 绑定 `AsyncReset`。内嵌 SV 的复位端口声明为 `AsyncReset`，不依赖默认复位推断。
- 复位持续 128 拍。能在这段时间内通过清零有效位或正常时钟传播进入安全状态的数据寄存器保持无复位。独立的 `clear`、`flush` 等操作命令保留原有同步语义。
- 验证复位时，至少施加一次不跨时钟有效边沿的复位脉冲，检查状态在复位断言时生效；注明各时钟域的复位释放约束。

## FSM 标准

编写或审查任何 FSM、状态转移或控制输出时，必须读取 [references/fsm.md](references/fsm.md)。核心要求：

- **仅对执行路径明确、阶段互斥的控制使用单一 FSM**；路径可以分支和自环，但不能用状态枚举强行串行化独立并发行为。
- 存在并发或乱序条件时，必须用独立 flag 配合 FSM，或采用纯 flag 控制；可独立发生、完成和保持的事实不要编码成所有组合状态。
- **推荐 one-hot 状态编码**，使用 `typedef enum logic [...]` 和具名状态；非 one-hot 实现需有明确约束或理由，不在纯风格重构中擅自改变已有固定编码。
- One-hot FSM 用模块体内的 `localparam integer <STATE>_BIT` 声明状态位索引；枚举值由该索引移位生成，正常状态译码用 `state_q[<STATE>_BIT]`。非法状态检测和恢复按完整状态判断。
- 复杂 FSM 可按职责和独立执行路径拆成若干子 FSM，通过明确的事件、握手和 flag 协调，不构造庞大的全局组合状态。
- 默认三段式：状态寄存使用 `always_ff`，FSM 次态逻辑统一使用 `always_comb`，通过 `case` 或 `if/else` 表达状态转移；输出译码优先使用 `wire` + `assign`；输出需要 `case` 或多级分支以改善可读性时使用 `always_comb`；明确复位状态、状态保持、转移条件、冲突优先级及非法状态行为。
- 每条路径完整产生次态与组合输出，遵守单次赋值；禁止常见的 `state_d = state_q; case (...) ...` 默认后覆盖写法。
- 区分 Moore/Mealy 与注册输出，不改变接口周期、脉冲宽度和握手语义；三段式不等于给输出额外加寄存器。
- 若既有微架构确需不同组织，不为套模板改变功能；说明偏离原因，但不能绕开单驱动、单次赋值及完整组合赋值规则。

## 去冗余与语义边界

- 删除仅重命名、拆包后立即重打包、重复扩展和无效包装；保留确有复用、类型边界或明确硬件语义的模块。
- 不为减少行数替换既有选择/归约语义；尤其保留优先级、并发命中、未知值处理、数据排序及条件屏蔽行为。
- 根据数值范围确定位宽与符号，需要时显式转换；检查单元素、最小/最大参数、非二次幂范围、空循环、负切片及溢出。
- 保持原有复位极性、未复位数据、使能、流水延迟、转发与协议约束；发现同步复位时按第 8 条处理。
- 不引入锁存器、组合环、隐式多驱动或未经设计的时钟/复位路径；跨时钟域问题不能靠普通组合重写解决。
- 无测量不宣称面积、时序或仿真性能收益。

## 工作流与审查输出

1. 读取适用仓库说明与目标实现，识别参数、时钟/复位、接口时序及测试。对内嵌 SV 同时检查宿主字符串插值与转义。 检查端口的显式 wire/logic、实际驱动方式和纵向对齐；SvImpl 同时检查 Bundle、Decoupled/Valid 分组及展平后的 SV 接口。
2. 修改时做最小范围、行为保持的调整；审查时分别标记行为缺陷与风格违例，报告 `文件:行号`、问题、影响和具体改法。
3. 检查组合逻辑是否优先使用 `wire`、generate 循环和 `assign`，`always_comb` 是否用于更清晰的 `case` 或多级分支；允许省略 `generate/endgenerate`，检查展开条件是否为常量；全局模式分支是否在外层；共享变量是否集中、局部声明是否合理；每 bit 的驱动、路径与索引是否唯一。检查变量声明、实例参数与端口连接是否逐项独立成行，各分支是否用 `begin/end` 且分支体另起一行，重复硬件逻辑是否用小模块复用，以及空行和必要注释是否按小功能点组织。
4. 检查数组归约依赖、组合完整赋值、无锁存器/环、位宽与边界；涉及控制逻辑则先检查 FSM/flag/子 FSM 的建模选择，再检查状态编码、转移表、flag 生命周期、输出时序与非法状态策略。
5. 运行可用的 lint/编译及定向、随机回归，覆盖配置分支和参数边界；纯重构尽量做旧版对比或参考模型检查。FSM/flag 加测自环、并发事件、乱序完成、同周期置位/清零、子 FSM 协同、复位、停顿和非法状态处理。
6. 记录实际命令与结果；明确未跑测试、工具限制及未做性能测量。不要通过关闭 warning 掩盖新问题，也不要把风格合规等同功能正确。
