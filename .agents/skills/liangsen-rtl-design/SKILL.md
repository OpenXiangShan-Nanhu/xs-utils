# Liangsen RTL Design

面向通用可综合 RTL，而非某个模块或某种微架构。适用于独立 `.sv`、生成器模板及内嵌 SV；不把特定 FIFO、仲裁器或协议的行为推广成通用要求。纯审查给出发现，修改任务才编辑代码，始终限制在用户指定范围内。

## 必须遵守的规则

### 1. 过程式循环优先

- 组合计算优先使用 `always_comb` + `for (integer i = ...; ...; i++)`，用阻塞赋值 `=`；涵盖地址、掩码、前缀、归约、译码和数据选择。
- 批量寄存器更新使用 `always_ff` + 过程式 `for`，用非阻塞赋值 `<=`；按时钟、复位与控制语义合理组织进程，不逐元素生成独立进程。
- **`generate for` 只用于批量模块例化**。纯计算和赋值移到过程式循环；例化循环内不混入本可移出的计算。
- 简单连接、原生归约和单条表达式可直接使用 `assign` 或 wire 连续赋值，无需添加无意义的 `always_comb` 包装。

### 2. 编译期配置使用外层 generate if

- 特性开关、实现模式等 elaboration-time 参数用显式外层 `generate if ... else ... endgenerate` 选择实现，分支内再用 `always_comb/always_ff + for`。
- 不将参数选择嵌入每 lane 的循环体、过程式 if 或重复三目表达式。参数参与位宽、索引和普通算术本身不受此限制。
- 公共逻辑提取到分支外，不在各分支复制；运行时输入控制仍用过程式 `if/case`，不能放进 generate 条件。

### 3. 信号在循环外集中声明

- 数据临时量、向量、数组和矩阵在模块作用域声明，位于循环及 generate 分支之外；循环中只通过元素或切片索引访问。
- 禁止在过程式循环体或 generate for 中声明局部数据变量、wire、logic；`integer/genvar` 循环控制索引可在 for 头部声明，但不能兼作归约累加器。
- 函数的临时量在函数作用域开头声明，仍遵守单次赋值；不得借函数或任务隐藏重复累计、共享可变状态。
- 过程式目标使用 `logic`；连续驱动或子模块输出可连接 `wire`。不要把 wire 连续赋值改成仅初始化一次的 logic 声明。

### 4. 每 bit 单次赋值

**一次组合求值或一次时序更新内，每个实际目标 bit 最多赋值一次；同一互斥条件结构中的多分支赋值算一次。** 按驱动源、索引映射和可执行路径检查，不按赋值语句数量机械统计。

- 组合目标每 bit 必须在所有路径恰好赋值一次；时序目标允许在未使能时不赋值以保持状态。
- 完整的 `if/else`、`case/default` 可在各互斥分支赋值同一目标；分散的多个 if 不得仅凭“通常不会同时触发”视为互斥。
- 禁止“先默认赋值，再覆盖”、整向量/整数组清零后重写部分元素、临时结果算出后原地修正。使用完整互斥分支、单一表达式或独立中间阶段。
- 循环可写不同元素或不重叠切片；审查动态索引、地址冲突和位宽截断，证明不同迭代不会写同一 bit。无法证明时改为按目标组织选择逻辑。
- 每 bit 仅一个有效驱动源；互斥 generate 分支中只有被选择的实现存在，不算多驱动。
- 循环索引递增和跨时钟周期更新不违反规则。`counter <= counter + delta` 的状态递推不等于同一组合求值中的反复累计。

### 5. 手写归约必须使用数组阶段

- 禁止 `acc = acc op term[i]`、`acc += ...`、`result |= ...` 等单变量循环归约；标量或向量均禁止，藏进函数/任务同样禁止。
- 求和、计数、AND/OR/XOR、min/max、前缀与优先级累计都使用模块作用域的阶段数组或树节点数组；seed 与后续目标分离，每个元素写一次。
- 数组不是形式包装：反复写 `stage[0]`、先初始化整个数组再覆盖、通过后续迭代覆盖结果实现优先级仍违规。
- 顺序扫描与树形归约均可，但须按依赖顺序写不同阶段/节点。数组写法不自动等于平衡树；不要在纯风格重构中擅自改变关键路径结构。
- `|mask`、`&mask`、`^mask` 等原生归约表达式没有可变累加器，可以直接使用；不要求为它们制造无意义数组。
- 写法与反例见 [references/rtl-patterns.md](references/rtl-patterns.md)；实施或审查归约、前缀、索引写入时读取该文件。

### 6. 批量操作与复杂计算附 Chisel 等效紧凑注释

- 批量映射、矩阵匹配、前缀/归约、复杂选择、地址变换和批量寄存更新，在对应代码块前添加 `// Chisel equivalent:` 注释，优先用一至三行展示整体运算，而不是逐句翻译 SV。
- 使用能准确概括行为的 `VecInit`、`map/zip`、`scanLeft`、`reduce/reduceTree`、`PopCount`、`Mux1H/PriorityMux` 等紧凑写法；变量名对应实际信号，参数对应编译期配置，读者应能一眼看出输入、输出与操作。
- 等效注释必须核对位宽、符号、截断、lane/bit 顺序、选择优先级、多命中/无命中及边界输入语义。`+` 与 `+&`、普通归约与树形结构不能无说明地互换。
- 时序块的注释须体现寄存延迟、使能和复位；不能用纯组合表达式冒充寄存更新。只描述组合最终结果时，不暗示中间结构或时序也等价。
- 注释中的函数式 `scanLeft/reduce` 是表达算法意图，不违反 SV 禁止单变量循环累计的规则；实际 RTL 仍须用独立数组阶段并遵守每 bit 单次赋值。
- 无法用简短表达式准确覆盖实现时，分成少量具名步骤；若只示意结构或受特定条件约束，明确标为 `Chisel-style structure:` 或写出等价前提，不用虚构 helper 掩盖核心算法、冒充完整等价。
- 简单直接连线不必机械加注释；修改逻辑时同步维护注释，审查时检查缺失、过期或误导性的等价描述。示例见 [references/rtl-patterns.md](references/rtl-patterns.md)。

### 7. 端口显式声明类型并对齐

- SV 模块的输入、输出必须显式声明 `wire` 或 `logic`；输入统一使用 `input wire`，`inout` 使用 `wire`。
- 只有端口本身直接在 `always_comb`、`always_ff` 或其他 `always` 块中赋值的输出使用 `output logic`；由 `assign`、子模块输出或其他连续连接驱动的输出统一使用 `output wire`。内部寄存器经 `assign` 连到输出时，输出仍是 `wire`。
- 同一端口列表每行声明一个端口，用空格纵向对齐方向、`wire/logic`、packed 位宽和端口名；标量在位宽列留空，使标量和向量端口名对齐。修改位宽或名称后重新检查整组对齐，内嵌 SV 同样遵守。
- Scala/Chisel 的 SvImpl 优先使用 Chisel 类型声明端口；`io_` 开头的信号统一收进 `val io = IO(new Bundle { ... })`，字段去掉 `io_` 前缀，调用处使用 `core.io.xxx`。已有具名 Bundle 可继续复用，时钟和复位保持独立 `IO`。
- `valid(1b)-bits-ready(1b)` 信号组使用 `Decoupled(payload)`，输入端使用 `Flipped(Decoupled(payload))`；`valid(1b)-bits` 信号组使用 `Valid(payload)`，按方向使用 `Input/Output` 或 `Flipped`，不得拆成独立握手字段。
- 多路 packed valid/ready 掩码保留为 `UInt(laneCount.W)` 和相应 packed bits，不能当作单个握手组；也不因参数暂时为 1 而改变字段类型。
- Bundle 层级展平后的端口名、方向和位宽须与 SV 模板一致；重构时同步封装、直接调用处及测试，检查生成接口与模板匹配。

## FSM 标准

编写或审查任何 FSM、状态转移或控制输出时，必须读取 [references/fsm.md](references/fsm.md)。核心要求：

- **仅对执行路径明确、阶段互斥的控制使用单一 FSM**；路径可以分支和自环，但不能用状态枚举强行串行化独立并发行为。
- 存在并发或乱序条件时，必须用独立 flag 配合 FSM，或采用纯 flag 控制；可独立发生、完成和保持的事实不要编码成所有组合状态。
- **推荐 one-hot 状态编码**，使用 `typedef enum logic [...]` 和具名状态；非 one-hot 实现需有明确约束或理由，不在纯风格重构中擅自改变已有固定编码。
- 复杂 FSM 可按职责和独立执行路径拆成若干子 FSM，通过明确的事件、握手和 flag 协调，不构造庞大的全局组合状态。
- 默认三段式：状态寄存 `always_ff`、次态计算 `always_comb`、输出译码 `always_comb` 或简单连续表达式；明确复位状态、状态保持、转移条件、冲突优先级及非法状态行为。
- 每条路径完整产生次态与组合输出，遵守单次赋值；禁止常见的 `state_d = state_q; case (...) ...` 默认后覆盖写法。
- 区分 Moore/Mealy 与注册输出，不改变接口周期、脉冲宽度和握手语义；三段式不等于给输出额外加寄存器。
- 若既有微架构确需不同组织，不为套模板改变功能；说明偏离原因，但不能绕开单驱动、单次赋值及完整组合赋值规则。

## 去冗余与语义边界

- 删除仅重命名、拆包后立即重打包、重复扩展和无效包装；保留确有复用、类型边界或明确硬件语义的模块。
- 不为减少行数替换既有选择/归约语义；尤其保留优先级、并发命中、未知值处理、数据排序及条件屏蔽行为。
- 根据数值范围确定位宽与符号，需要时显式转换；检查单元素、最小/最大参数、非二次幂范围、空循环、负切片及溢出。
- 保持原有复位极性、同步/异步属性、未复位数据、使能、流水延迟、转发与协议约束；不凭示例擅自规定所有模块的复位方式。
- 不引入锁存器、组合环、隐式多驱动或未经设计的时钟/复位路径；跨时钟域问题不能靠普通组合重写解决。
- 注释用 Chisel 紧凑等效写法概括批量操作和复杂计算，并说明必要的约束与时序原因，不逐句翻译代码；无测量不宣称面积、时序或仿真性能收益。

## 工作流与审查输出

1. 读取适用仓库说明与目标实现，识别参数、时钟/复位、接口时序及测试。对内嵌 SV 同时检查宿主字符串插值与转义。 检查端口的显式 wire/logic、实际驱动方式和纵向对齐；SvImpl 同时检查 Bundle、Decoupled/Valid 分组及展平后的 SV 接口。
2. 修改时做最小范围、行为保持的调整；审查时分别标记行为缺陷与风格违例，报告 `文件:行号`、问题、影响和具体改法。
3. 检查每个 genvar 是否仅服务模块例化；参数分支是否在外层；数据变量是否在循环外；每 bit 的驱动、路径与索引是否唯一；批量操作和复杂计算是否有准确、紧凑且与当前实现同步的 Chisel 等效注释。
4. 检查数组归约依赖、组合完整赋值、无锁存器/环、位宽与边界；涉及控制逻辑则先检查 FSM/flag/子 FSM 的建模选择，再检查状态编码、转移表、flag 生命周期、输出时序与非法状态策略。
5. 运行可用的 lint/编译及定向、随机回归，覆盖配置分支和参数边界；纯重构尽量做旧版对比或参考模型检查。FSM/flag 加测自环、并发事件、乱序完成、同周期置位/清零、子 FSM 协同、复位、停顿和非法状态处理。
6. 记录实际命令与结果；明确未跑测试、工具限制及未做性能测量。不要通过关闭 warning 掩盖新问题，也不要把风格合规等同功能正确。
